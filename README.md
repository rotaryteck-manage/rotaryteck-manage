# Rotaryteck Manage

擎正科技的案件、庫房、收領料、照片與員工權限管理系統。

## 專案結構

- `dist/`：前端畫面與 Excel BOM 元件
- `worker/`：Cloudflare Worker 後端 API
- `drizzle/`：D1 資料庫遷移
- `tests/`：權限、庫存、照片與資料驗證測試
- `wrangler.jsonc`：Cloudflare Worker、D1 與 R2 綁定設定

## Cloudflare 設定

Worker 名稱：`rotaryteck-manage`

必要綁定：

- D1 `DB` → `rotaryteck-manage-db`
- R2 `UPLOADS` → `rotaryteck-manage-uploads`

必要環境變數：

- `SUPABASE_URL`：一般文字
- `SUPABASE_PUBLISHABLE_KEY`：一般文字
- `SUPABASE_SECRET_KEY`：加密祕密

不要把密碼或 Secret key 寫入程式碼或提交到 Git。

## 指令

- `npm run build`：建立 Worker 程式
- `npm test`：執行測試
- `npm run deploy`：套用 D1 遷移並部署 Worker

首次部署後，先在 Supabase Authentication 建立主管登入帳號。第一位成功登入的帳號會成為主管，之後可在管理後台建立其他員工與初始密碼。

## 權限

- 一般員工：查看授權區域、回報自己的每日工作
- 庫房管理：收料、領料及上傳照片
- 主管：依後台權限設定使用；預設較高權限不代表不可撤銷。每週排程預設主管，每日與料件預設主管/倉管。
- 自訂權限與人員排序可獨立設定，後端同樣檢查權限。

照片預設保存在私人 R2，並由後端驗證登入與權限後才可讀取。

## v19：電鍍管理

- 上方獨立「電鍍管理」頁籤，案名方框桌面每列 3–4 格，手機依寬度換行。
- 同案各次送鍍集中管理；每次可新增多組環片配置（每組片數 × 組數），自動加總。
- 再次送鍍複製已儲存配置，可自由更改；回貨日期與品檢清空，不修改舊紀錄。
- 登記實際回貨日期，品檢分待品檢／合格／異常；無預計回貨日。
- 倉管、主管可登記；一般員工僅查看。主管後台可管理案件、紀錄、排序及本區文字。
- 方框拖曳或前後移動後儲存於共享資料；操作紀錄保留人員、時間與內容。
- 新增 platingProjects、platingText 共享狀態欄位，舊資料可直接載入，無新增 SQL migration。
- 測試：33 項 Node 測試；另以 DOM 模擬驗證完整新增／回貨／再送鍍／文字設定流程。
- 本次未在實際瀏覽器與正式雲端環境驗證。請部署後用測試案件檢查桌面、手機畫面及儲存。

## v20：電鍍出貨單照片

- 每筆已儲存的送鍍紀錄可上傳多張出貨單照片；不同案件、不同次送鍍分開存放。
- 大於 2 MB 的 JPG／PNG／WebP 沿用自動壓縮，伺服器限制每張 2 MB。
- 預設收合，以圖片編號與上傳時間列出；點擊開啟照片。
- 倉管／主管可上傳及刪除，一般員工可查看；操作留下人員與時間紀錄。
- 再次送鍍不複製照片。相關介面文字可在電鍍管理後台設定。
- 已驗證照片 API 權限、案件與送鍍隔離、大小限制，以及 DOM 模擬上傳、刪除、保留未儲存欄位；尚未正式上線測試。

## v21：照片集中查看與完整匯出

- 每次送鍍內提供「上傳出貨單」「上傳表面積截圖」兩組選檔及上傳按鈕，不再放照片清單。
- 點進案名後以單一收合區列出所有照片，名稱為「第 N 次送鍍出貨單／表面積｜人員｜上傳時間」。舊照片預設歸類為出貨單。
- 倉管與主管可匯出本案或全部案件的 ZIP：送鍍紀錄 CSV、操作紀錄 CSV、照片清單 CSV，以及依案名／次數分類的照片。
- 沒有照片也能匯出紀錄；照片讀取失敗時不產生不完整的 ZIP。
- 已通過 36 項 Node 測試、DOM 操作模擬，以及 ZIP 內容檢查。尚未正式部署或於實際瀏覽器驗證版面。
