# 12.7v：鈴鐺入口與裝置狀態還原

## 本次範圍

只修正手機／電腦的通知入口、未讀數字定位、裝置狀態檢查，以及更新版本顯示。後端 worker 原始碼、通知加密及發送流程、Cron、資料庫結構、權限、收件人、通知時間與文字設定、CSS、其他功能均維持 12.6v。

工作回報 17:15 發送、17:25 收到屬於另行觀察的延遲，本版沒有調整那段發送程序。

## 查到的關聯

1. 後台刪除裝置只移除伺服器的裝置紀錄，不會在那台電腦直接執行瀏覽器 unsubscribe。因此瀏覽器可能仍保留訂閱，而伺服器已找不到對應裝置。
2. 停用裝置則保留裝置紀錄並設為停用。兩種操作本身都是有效管理設定，不能當成暫時失敗後自動恢復。
3. 舊程式只讓「已綁定且啟用」的按鈕成為鈴鐺；失去該狀態就改成文字按鈕。未讀刷新卻照常附加絕對定位的數字，沒有鈴鐺的相對定位後便跑到頁面右上角。
4. 舊點擊邏輯也以綁定狀態決定能否開啟通知清單，因此被停用／刪除後就算有站內通知也無法正常查看。
5. 訂閱讀取錯誤曾被轉成 null，且多次非同步檢查沒有新舊順序保護，可能把暫時失敗或較舊結果顯示成未綁定。

本地已重現上述程式情境；這不能單獨證明使用者當次電腦的實際裝置紀錄，但停用／刪除確實能觸發原問題。

## 修正邏輯

- 已登入使用者的鈴鐺固定開啟「我的通知」，站內通知不再依賴系統推播是否啟用。未讀數字更新前先確保鈴鐺定位存在。
- 正常手機／電腦保留原本 42px 鈴鐺、數字位置與通知清單；不改 CSS。只有異常或未綁定時，在通知框內以小型狀態列說明原因。
- 狀態分成確認中、正常、尚未綁定／已刪除、裝置停用、人員停用、瀏覽器封鎖、不支援及金鑰更新。正常時小型狀態列隱藏。
- 已刪除／尚未綁定者可在通知框內明確點「開啟通知」，沿用原本註冊流程。原訂閱可用時直接重用，不因查看清單重新訂閱。
- 後台停用裝置或人員時不顯示重新啟用按鈕，也不自動新增、復原或啟用；需要由後台恢復。原後端停用控制完全保留。
- 狀態檢查不主動 unsubscribe；需要更換公鑰時，仍由使用者明確開啟通知後沿用原本更換程序。本次沒有更換任何 VAPID 金鑰。
- 等待通知服務啟動，讀取錯誤顯示確認中；暫時失敗／尚未讀到訂閱時最多追加兩次檢查，不無限輪詢、不自動綁定。
- 只接受最新且仍屬於同一登入人員、同一按鈕的結果；忽略晚到的舊結果。未讀刷新也核對登入者，避免換帳號後顯示前一人的數字。
- 重複點擊開啟通知時鎖住該操作，避免多次建立訂閱。
- 不會因此自動重推舊通知；沒有修改任何送達收據、防重複或歷史界線。

## 驗證

- 完整自動測試 422 項通過，包括新增 16 項鈴鐺、啟用狀態與後台刪除／停用回歸測試。
- Windows Edge、iPhone PWA、Android Chrome 為本地介面情境模擬，沒有冒稱已操作使用者的實體手機。
- 覆蓋正常綁定、停用裝置、停用人員、刪除後保留瀏覽器訂閱、明確重新綁定、權限封鎖、尚未授權、不支援、暫時讀取失敗、亂序回傳、切換帳號及未讀數字先到的情況。
- 後台真實 API 的本地資料庫測試確認：刪除不會刪掉站內通知；停用裝置即使再提交訂閱也保持停用。
- 全部 64 個瀏覽器腳本合併語法檢查通過。
- 核對 worker、drizzle、wrangler.jsonc 及全部 CSS 與 12.6v 一致。
