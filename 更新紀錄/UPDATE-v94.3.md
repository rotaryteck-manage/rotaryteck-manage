# v94.3

基於本次 v94.2 修正，僅打包差異檔案。

- 修正補貨刪除呼叫 wireCommit 少傳 detail 欄位，導致後端拒絕「資訊庫紀錄格式不正確」。保留後端格式檢查與權限，不放寬資料驗證。
- 雲端儲存使用獨立 modal dialog 小框，顯示於瀏覽器最上層；等待時暫時隱藏原大型視窗，結束後還原。刪除按鈕同樣走這個流程。
- 提示文字放進目前開啟的對話框，避免被遮住；補貨刪除失敗先還原名單，再顯示實際錯誤。
- 我的通知中，舊 /#wire 連結改開補貨名單，舊 /#plating 改開電鍍總覽。已有指定紀錄參數的通知保持精準跳轉。舊通知沒有紀錄編號時無法還原成單筆目標；不把一般頁籤點擊改為彈出名單。
- 通知文字設定不變。沒有證據顯示本次格式錯誤就是所有 HTTP 503 的原因，若仍有真正 503，需再取得錯誤回應排查。

## 部署與驗收
依原路徑覆蓋至 v94.2 專案後重新部署，確認上方顯示 v94.3。
若目前未儲存內容只有失敗的測試刪除，可按「放棄變更並重新載入」後再測；不要重試舊版產生的錯誤請求。若還有其他未儲存內容，請先下載未儲存資料留存。
1. 不勾選補貨紀錄直接按刪除，應在名單前方看到選取提示。
2. 單筆及多筆刪除已入庫紀錄，確認上傳小框置中、無大型視窗遮擋；重整後紀錄已消失，原線材及其他紀錄保留。
3. 我的通知 → 舊線材通知開補貨名單，舊電鍍通知開總覽；有編號的新通知仍開對應紀錄。
4. 儲存失敗時原視窗恢復，錯誤可見。
