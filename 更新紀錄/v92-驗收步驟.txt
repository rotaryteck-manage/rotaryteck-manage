Rotaryteck Manage v92 驗收步驟

一、部署前
1. 使用本次差異更新包覆蓋對應檔案。
2. 執行 npm run deploy，確認 0022_notifications92.sql 遷移成功。
3. 重新整理網站；手機若仍看到舊畫面，關閉網站後重新開啟一次。

二、線材／電鍍彙整
1. 準備多筆符合提醒條件的線材資料。
2. 等下一輪排程通知。
3. 同一位接收人應只收到一則線材摘要，內容顯示未處理筆數，不應再收到 11 或 33 則相同訊息。
4. 電鍍提醒用相同方式檢查。

三、工作排程與工作回報
1. 將每日工作提醒時間設在未來 5 分鐘內，並替測試人員安排當日工作。
2. 確認到時後收到工作排程提醒。
3. 將工作回報提醒設在另一個未來時間，確認只有當日有安排工作且尚未回報的人收到。
4. 後台通知紀錄應顯示正確人員及各裝置結果。

四、裝置辨識
1. 後台打開「裝置通知狀態」。
2. 替手機及電腦分別重新命名，例如「黃瑞麟 iPhone」、「辦公室電腦」。
3. 發送一則測試通知。
4. 在「測試通知紀錄」確認操作者、接收對象、成功台數與來源。
5. 正式通知紀錄展開後，應能看出成功的是哪一台裝置。

五、測試通知防誤發
1. 點「發送測試通知」或通知規則中的預覽發送。
2. 未按確認時不得送出；按確認後才會發送。
3. 發送後個人鈴鐺不得新增測試通知。
4. 後台正式通知列表不得混入測試通知；測試通知只出現在獨立測試紀錄。

六、Excel 匯出
1. 後台點「匯出通知紀錄」。
2. 選擇日期、分類與狀態後匯出。
3. Excel 應包含通知總覽及各分類工作表，並列出接收人員、裝置名稱、狀態、時間、重試次數與錯誤。
4. 未勾「包含測試通知紀錄」時不應出現測試工作表；勾選後應新增「測試通知」工作表。

七、排程畫面回歸
1. 檢查每日排程與每週排程。
2. 確認 v91.1 的版面、色框、假日、日期及複製圖片效果完全未變。
