# v71 更新紀錄

接續版本：v70。此包為更新包，尚未部署到線上。

## 本次 13 項更新

1. 所有現有照片上傳欄位支援電腦 Ctrl＋V：料件、工作回報、收據、送鍍／區域照片、網站 LOGO、手機圖示。保留選檔，增加預覽及移除；有多個照片欄位時，先點目標欄位的「點此後按 Ctrl＋V 貼上照片」。貼上不會自行提交上傳。
2. 每日月曆上的料件案件按鈕直接依類型顯色：收料淡綠、出貨淡藍、送貨淡紫，與明細一致。
3. 主管可編輯所有人的手動料件紀錄，並可修改登記人；既有庫存收／領料紀錄也增加編輯鍵，可修改日期、類型、案件、料件名稱、數量、登記人與替換／新增照片。既有紀錄調整同步校正庫存和累計收料，保存修改前後文字紀錄。
4. 「複製上週」點擊即顯示處理視窗，前端阻擋連點，後端以同週唯一標記及交易避免重複寫入。再點顯示已完成；完全相同的舊版已複製項目也不重複新增。失敗可重試，整批失敗不留下半套資料。
5. 每週上方新增「重置本週排程」，確認後清除此週排程、備註及複製標記。保留工作回報、上週原排程與跨週工作在其他日期的部分，可重新複製。
6. 每週色塊上的刪除與編輯按鈕統一寬高、字體、圓角和對齊。
7. 瀏覽器分頁小圖示改用網站公司 LOGO，與手機主畫面圖示分開。
8. 工作文字統一顯示為「姓名　【工作項目】 _ (工作內容)」。每日工作紀錄的項目以排程設定色標示，姓名與工作仍在同一行。
9. 每週、每日工作項目改為共用下拉選單。管理後台「工作排程」新增「管理工作項目選單」，主管可逐行新增、修改或刪除；工作內容維持自由輸入。已存工作保留原文字，刪除選項不刪除舊排程。
10. 新增料件未附照片時，儲存前提供「返回補照片／確認儲存」。
11. 每週／每日按鈕旁增加同大小的「文字記錄」，僅主管可見及存取。可切換每日／每週並選日期範圍，以「時間｜人員｜操作內容」呈現，每筆有刪除與確認；只刪文字，不撤銷排程、回報或庫存。既有排程、料件及回報提供目前內容紀錄；v71 起另保存操作紀錄，無法回溯舊版沒有保存的歷次修改。
12. 點右上角姓名可選帳號並輸入密碼切換。切換前提醒未儲存輸入；錯誤保留原登入，成功後重新載入新帳號資料與權限。其他開啟中的分頁也會重新載入。正在儲存／上傳時先完成原操作。
13. 料件紀錄照片保持原顯示尺寸，點擊可開啟大圖，提供放大／縮小，按 × 或 Esc 關閉後保留明細與原捲動位置。

## 核對與操作提醒

- 工作項目選單：管理後台 → 工作排程 → 管理工作項目選單，每行一項。
- 舊紀錄有同名不同規格、缺少料件 ID 時，主管須選擇正確的原庫存料件；不會任意推測庫存歸屬。已封存的料件也能選取。修改若造成負庫存會阻擋。
- 舊版已經產生的多餘重複排程不會自動刪除。可核對後使用「重置本週排程」，再重新複製。
- 「重置本週」指目前畫面選擇的週別，確認視窗顯示實際日期。
- 分頁 LOGO 使用目前網站已上傳的公司 LOGO；瀏覽器若仍暫存舊圖示，可關閉分頁後重新開啟。

## 套用更新

1. 先保留目前專案檔案及資料備份。
2. 將更新包內容覆蓋至 v70 專案根目錄，保留原有環境設定、資料庫與上傳儲存空間。
3. 沿用原部署流程。新增 `drizzle/0010_schedule_usability71.sql`，正常 `npm run deploy` 會先套用資料庫 migration 再部署。
4. 已附重新建置的 `dist/server/index.js`；自行重新建置時須一併覆蓋 `build.mjs` 和兩個新增的 v71 前端檔案。
5. 部署後重新整理頁面，再依上列 13 項核對。

新資料表皆使用 IF NOT EXISTS，不清除既有資料；服務亦可按需建立，以相容原更新方式。

## 驗證

- 整站模擬帳號驗證：錯誤密碼保留原帳號；成功切換後主管功能不再對一般員工顯示。
