# 10.2v 排程月曆追加修正

基礎：已套用「Rotaryteck-10.2v-schedule-speed-changes.zip」的完整專案。此包只包含本次差異檔案，尚未部署；網站顯示版本維持 10.2v。

## 本次內容

1. 進入排程時，獨立的排程、回報、人員與備註讀取同時開始，減少逐項等待；照片統計仍保留上一包的日期範圍限制。雲端資料同步完成前不會把舊資料當新資料。
2. 手機、電腦日曆當天內容固定「工作紀錄 → 請假紀錄 → 新增料件」。新增料件依建立時間由舊到新，同一時間以編號穩定排序；編輯不改建立時間。
3. 今天若是假日（週末或政府標示休假），以淡紅底、紅框和深紅日期標籤呈現；平日的今天維持綠色。
4. 政府假日名稱如「補假」、「國慶日」在日期下方顯示淺紅底、細紅框的小標籤，手機和電腦一致。一般週末只有淡紅的日期格，不額外產生「假日」文字。

## 部署後檢查

- 電腦與手機首次進入排程，確認能顯示當月資料；可各記錄等待秒數，與上一版比較。正式站速度仍受雲端和網路影響。
- 同日依序新增「105、105、測試、測試」，確認日曆顯示「工作紀錄、請假紀錄、105、105、測試、測試」。重新整理及編輯其中一筆後順序不變。
- 查看有「補假」、「國慶日」的日期：名稱在日期下方有獨立小框，工作／料件框仍在其下方。
- 在平日查看「今天」：維持綠色。逢週末或休假日的當天再確認「今天」呈淡紅與深紅；不需要調整裝置日期或系統時鐘。
- 手機切換月份、選擇日期，確認休假日選取框也是紅色；平日選取框維持原本綠色。
- 新增或刪除後重新整理，確認資料確實儲存在雲端；同時檢查工作回報、請假、照片仍可打開。

## 驗證

- `npm run build` 與完整回歸測試通過；另有手機、電腦的新增順序案例。
- 未量測正式網站的等待時間，部署後以實際網路和資料量驗收。
