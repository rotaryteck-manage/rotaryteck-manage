# 12.6v 更新內容與程序邏輯

本次只處理通知交付診斷與訂閱同步、料件存檔等待、排程／週會文字設定。沒有修改 CSS、既有框框尺寸、排版、權限、通知時間、收件人設定、請假計算、品檢操作、排程複製內容或頁面更新頻率。

## 通知

- 核對 12.3～12.5 原始碼，12.5 的排程路徑仍使用原生 Web Push 發送器，沒有改回先前不支援的 redirect:error。
- 獨立解密器已驗證實際 workerd 執行產出的密文可讀。現有證據不足以確定所有手機未顯示的根因，因此不能把後台「成功」當成手機實際已收到。
- 重新進站時依目前實際 endpoint 核對訂閱加密金鑰；只在該人與該裝置都啟用且金鑰不一致時同步。保留 endpoint、裝置識別、管理員停用與歷史防重複收據，不重新訂閱、不改 VAPID 金鑰。
- Service Worker 更新不經快取；收到推播後立即呼叫 showNotification，不等待回報或未讀數查詢。
- 每台通知附帶有期限的 HMAC 回報憑證。裝置回報「已接收」、「已執行通知顯示」或顯示錯誤。後台展開該裝置可看到這些資訊；它們和推播服務接受狀態分開。
- 「已執行通知顯示」只表示瀏覽器 showNotification 成功，仍不保證手機一定顯示橫幅、發出聲音或使用者看到。舊版 Service Worker、離線或回報失敗會沒有裝置回報，不可直接判定沒收到。
- 回報端點驗證簽章、七天效期與大小，不接受任意裝置狀態修改；回報不會寄信、不會改發送狀態、不會因缺回報就重推。

## 料件儲存與背景通知

1. 必要照片先壓縮、上傳；前端每次最多並行壓縮兩張，順序維持。
2. 資料、操作紀錄、舊照片清理待辦與新料件通知標記一起交易提交。寫入失敗則不建立通知。
3. 回傳剛儲存的一筆資料，畫面只更新這筆，不為了儲存重新載入整份工作排程。既有工作回報上傳流程維持。
4. 由背景驗證請求建立收件人待辦並凍結原始裝置名單，逐台在獨立請求發送。網路／資源中斷時，持久待辦由既有三分鐘排程接續，不依賴網頁保持開啟。
5. 已成功的裝置不重送；編輯既有料件不新增通知。新主管、新倉管或新增裝置不補收已凍結的舊通知。
6. 沿用原有分類、通知文字、收件人判斷、排除登記人與精準跳轉。沒有掃描舊料件補建通知；舊通知防重複與更新界線保持。
7. 資料儲存仍須等待必要照片與交易完成；這次移除的是推播服務等待、重複解析上傳表單與全區資料重載，並不承諾大照片立即存好。

## 文字設定

- 「週會紀錄」文字與操作按鈕併入後台「修改排程文字／按鈕」；通知規則、通知內容與收件人仍在通知設定，原設定保留。
- 新增「工作紀錄：複製排程按鈕」獨立文字欄位，預設「複製排程」，避免通用「複製圖片」對照把名稱改錯。日期選擇與複製處理不改。
- 週會標題、欄名、複製圖片／編輯／刪除、地點選項與翻頁等列入同區文字編輯。更改地點的顯示文字不改儲存值。
- 品檢報告新增操作文字補入共用文字設定目錄，也保留原有「補充其他畫面文字」方式。

## 驗證

- 完整自動測試 406 項通過。
- npm build 與 Wrangler 部署乾跑通過。
- 原生 workerd + D1 + WebCrypto：七人七次排程推播、一次料件推播、八筆裝置顯示回報；密文均由獨立解密器驗證，第二輪零重送。
- 測試沒有使用公司真實資料、真實手機 endpoint，或向真實推播服務發送通知。
- 本地 workerd 不模擬正式免費方案 10ms CPU 中止，正式 CPU 與實體手機通知仍須上線驗收。

資料庫新增遷移：0038_notification_receipts_material126.sql。此遷移只增加診斷欄位與料件待辦表，不重設歷史收據、通知規則或排程。
