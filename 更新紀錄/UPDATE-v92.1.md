# Rotaryteck Manage v92.1

更新日期：2026-10-03

## 通知可靠性修正

1. 更新部署沿用既有發送憑證，不再重新發送已完成通知。
2. 工作內容或項目修改後，原接收人不會重複收到當日提醒。
3. 發送時間後新增的人員不自動補發，需由主管按「補發」並選擇人員。
4. 線材與電鍍移除每日變動的識別方式，單次提醒不再每天重發。
5. 後台發送紀錄與防重複憑證分離，刪除紀錄不會造成重新發送。
6. 等待超過十分鐘的通知會恢復處理，暫時失敗最多重試兩次。
7. 料件、停班及其他即時通知失敗後，可由排程接續重試。
8. 同地區多條停班規則共用一次官方查詢，但每條規則仍獨立發送。
9. 停用所有料件規則後不再套用隱藏的預設通知。
10. 每輪最多實際發送 32 台，每日最多實際嘗試 200 台。
11. 已送過與重複判定的裝置不占本輪或每日額度。
12. 超過額度的通知保留，下一輪再處理，不會直接遺失。
13. 裝置改為每批四台並行，降低大量裝置造成排程逾時的機率。
14. 裝置連續失敗五次會自動停用，後台仍可手動恢復。
15. 登出時同步解除伺服器裝置綁定，避免留下無效裝置。
16. 每則推播使用獨立標記，手機同類通知不再互相覆蓋。
17. 規則在發送時間後啟用、改時間或改接收人，不會補送當天舊通知。
18. 國定假日、停班及一般排程使用一致的人員異動原則。

## 後台與資料修正

19. 後台通知紀錄改為可分頁讀取，不再固定只統計前 500 筆。
20. 測試通知記錄每台裝置的成功、失敗、延後與錯誤原因。
21. 後台顯示今日已用、剩餘與每日通知額度。
22. 自訂分類名稱會保存至正式紀錄及 Excel 匯出。
23. 清除按鈕改以實際裝置發送筆數顯示，避免組數與筆數混淆。
24. 正式發送及測試紀錄保存 90 天；防重複憑證保存 400 天。
25. 測試來源改顯示中文名稱。
26. Excel 日期改用真實日曆驗證，不接受 2 月 31 日等錯誤日期。
27. 雲端回傳非 JSON 時，顯示 HTTP 狀態與實際回應摘要，不再只顯示 JSON.parse。
28. 新增主管手動「補發」功能，避免系統自行補送又保留緊急補發方式。

## 更新方式

此差異包只包含 v92.1 修改檔案。覆蓋至 v92 專案後執行：

`npm run deploy`

部署指令會先建置，再套用 `0023_notifications921.sql`，最後部署 Worker。請勿只上傳 `dist/server/index.js` 而跳過資料庫遷移。
