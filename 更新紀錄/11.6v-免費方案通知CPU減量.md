# 11.6v 免費方案通知 CPU 減量

## 修改程序邏輯

1. 通知檢查維持每三分鐘一次：`*/3 * * * *`。
2. 照片、已刪除資料、過期通知及歷史紀錄清理，移至獨立的每小時第 1 分鐘排程：`1 * * * *`。不與三分鐘通知排程在同一輪執行；照片等過期實體資料清理最多比原排程晚約一小時。通知清單讀取時的七天清理仍保留。
3. 只讀取已到時間的通知規則需要的資料。尚未到期的線材或電鍍規則不讀取整個對應清單；工作提醒不查工作回報照片數。
4. 自動推播使用平台非同步 Web Crypto 及 fetch，避免原同步程式庫的加密／簽章 CPU 負擔。遵循 RFC 8291／8292，保留原 VAPID 金鑰、裝置訂閱、內容、跳轉及去重標記。
5. 手動測試、手動補發與即時通知保留原發送方式。假別重試仍隨三分鐘排程執行。
6. 不增加前台定時發送、頁面重新整理或 Loading。未改介面及排程資料。
7. 未開通付費方案、未提高付費資源額度，也未新增另一個 Worker；新增一個免費 cron trigger，須帳號仍有可用排程額度。

## 驗收項目

1. 官網右上角顯示 11.6v。
2. Cloudflare 中保留原三分鐘排程，另外有每小時清理排程。
3. 僅查看部署完成之後的新執行紀錄；舊版本的 error 不代表新版本結果。
4. 不按立即檢查／補發，等待兩輪三分鐘檢查，確認後台狀態與最新 Cloudflare outcome 不再是 exceededCpu。
5. 到期且符合條件的通知，後台及個人鈴鐺有紀錄；實際手機推播需另行確認。
6. 已送達通知不重複，停用人員及無權限人員不發送，新指派人員不補發舊通知。
7. 案件、庫房、線材、電鍍、工作排程的讀取、新增與儲存行為保持原樣。
8. 若新版本仍 exceededCpu，保存該筆完整紀錄，進一步按 CPU 實測拆分通知；不能以本地功能測試代替線上 CPU 驗收。

## 測試範圍

- 非同步加密產物由既有獨立 Web Push 解密器解密驗證。
- VAPID JWT 的 ES256 簽章、有效期、推播服務 audience 及金鑰輪替驗證。
- 真實金鑰、加密流程與模擬推播服務的自動排程整合測試。
- 推播服務 410 回應、重複執行去重、既有通知功能完整回歸。

本地測試不代表已在 Cloudflare 壓到 10ms 以下，須以正式部署後的 CPU/outcome 紀錄判定。
