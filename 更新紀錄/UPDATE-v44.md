# v44 四大管理區流程、後台整理與外觀設定

適用基礎：v43。此更新包尚未部署至正式網站。

## 更新方式

1. 在原網站「資料備份」下載完整 JSON 備份。
2. 解壓縮更新包，將其中 `dist`、`worker`、`tests`、`build.mjs`、`更新紀錄` 按原路徑覆蓋至原 GitHub 專案。請上傳解壓後的檔案，不是只上傳 ZIP。
3. 依原有 Cloudflare 流程部署。此次不需要新增資料庫 migration。
4. 部署完成後重新整理網站。舊 UPDATE 文件可繼續保留在「更新紀錄」資料夾。

## 1. 全站文字、配色與登入畫面

入口：管理後台 → 網站設定 → 全站文字、配色與 LOGO。

- 分成全站共用、案件、庫房、電鍍、線材、資訊庫、管理後台、登入畫面。
- 原有主要文字設定整合到同一入口，另提供提示文字搜尋及自訂文字替換。
- 可調整頁面、區塊、按鈕、表格、欄位、框線、文字與狀態顏色；各區未設定時沿用共用配色。
- 提供配色預覽、對比提醒、還原本區預設。儲存後生效。
- 登入畫面的文字、顏色可分別設定；前台、後台和登入頁共用公司 LOGO，可更換圖片及調整顯示尺寸。
- 顯示文字不會改變狀態代碼、資料名稱、計算與權限。設定會包含在完整 JSON 備份中。

## 2. 案件管理

- 原有日期保留為「預計完成日」，另外記錄「實際結案日」。
- 切換結案須確認，預設實際日期為台灣當日，可修正；重新開啟時清除實際結案日，保留預計日期與操作紀錄。
- 舊結案資料沒有實際日期時列為「待補日期」，不自行猜測。
- 支援案件／廠商跨年度搜尋、結案年度篩選及每欄每頁 10 筆。
- 未結案案件使用「調整排序」；結案依實際日期由新到舊顯示。

## 3. 庫房管理

- 同一個專案持續使用同一份庫存，不因新年度或結案而清空。
- 新增本次製作套數、開始日期、開始新一輪、製作歷史。
- 同輪調整套數會統一所有零件的套數；新一輪以現有庫存作為備料起點。
- 本次已備＝期初庫存＋本輪收到數量；領料不會讓已備進度倒退。
- 舊資料先保留原已收進度，明確開始新一輪後才改用庫存基準；舊套數不一致會顯示提醒。
- 新一輪開始後若尚未有後續操作，可確認撤銷；已有收領料或修改時會阻擋撤銷。
- 新增「更正收料」，須填差額與原因，同時更正已收與庫存，不以領料冒充更正。
- 匯出包含本次製作、累計已收、備料數量和製作歷史。

## 4. 電鍍管理

- 新增、修改送鍍資料須填焊接人員；缺少時提示並定位欄位，原輸入保留。
- 視窗中間內容可捲動，取消與儲存固定在底部。
- 未儲存時返回、關閉、取消或按 Escape 會先確認。
- 完成回貨日連動狀態；清除日期時確認改回送鍍中。
- 外部新增「沿用上次新增」，可選來源，只沿用配置；焊接人員、完成日和照片重新填寫。沒有紀錄時不可沿用。
- 同一批退回再送仍維持同筆紀錄，最終完整回貨時再填完成日。

## 5. 線材補貨

- 狀態以文字顯示：紅色需補貨、藍色進貨中、綠色足量。
- 倉管／主管勾選已訂購或已入庫，確認後記錄日期、時間、人員。
- 提供小型撤銷按鈕及再次確認；保留原登記和撤銷歷史。已入庫須先撤銷，才能撤銷訂購。
- 可直接登記入庫；員工仍可標記需補貨，但不會重設正在進貨中的紀錄。
- 入庫後保留在目前名單 7 天，時間、人員下方顯示橘色到期提醒；到期轉入補貨歷史，並非刪除。
- 新一輪需補貨會保留上一輪歷史，不將所有歷史疊在同一列。
- 同時修改同一線捆時沿用版本衝突保護，避免互相覆蓋。
- 補貨歷史可單獨匯出，線材整區匯出亦包含歷史。

## 6. 後台與資訊庫

- 員工、案件、庫房、電鍍、線材清單加入搜尋及 20／50／100 筆分頁。
- 員工名單與權限設定分頁顯示，操作按鈕集中於上方。
- 庫房名稱可直接開啟專案。
- 批量操作提供「全選本頁」、跨頁已選數量及刪除前確認。
- 新操作記入對應的資訊庫分類；原有個別文字紀錄刪除與權限保護保留。

## 驗證

- 88 項自動測試通過，涵蓋原有功能、補貨角色限制／撤銷／七日期限／版本衝突、備料基準、收料更正、結案日期及外觀設定公開範圍。
- 使用測試資料完成瀏覽器操作與桌面、390px 窄螢幕檢查，確認固定儲存列、長按鈕文字換行、同區按鈕等高，以及登入配色。
- 尚未操作正式網站的資料；正式環境仍須在更新檔上傳、部署後才生效。
