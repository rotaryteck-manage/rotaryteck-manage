# v24 儲存方式更新

這次改成按案件、操作紀錄、設定分筆儲存。儲存只傳送有變動的資料，不再受舊版「全部資料加起來 1.5 MB」的儲存限制。照片仍在原本 R2，不搬動照片，也不更動 Cloudflare 方案。

## 更新方式

1. 先等所有同事完成儲存，暫停輸入。
2. 從管理後台匯出全部資料／JSON 備份，保存到電腦。照片備份需另行匯出。
3. 將此 ZIP 解壓，把檔案依原有資料夾位置更新至 GitHub 專案。不要直接上傳 ZIP，也不要刪除其他原有檔案。
4. 等 Cloudflare 部署成功。原有 `npm run deploy` 會建立新資料表；後端也具備建表檢查。
5. 主管先重新整理網站，第一次讀取會自動轉換舊資料。確認案件、庫存、電鍍紀錄及照片能正常查看後，其他同事再重新整理使用。

舊頁面會拒絕儲存並提示更新，不會用舊版整包資料覆蓋新版資料。若有未儲存內容，先使用「下載未儲存資料」。

## 發生儲存問題時

- 網路中斷：可按上方「重試儲存」，同一次操作不會重複寫入。
- 同一筆資料已被別人修改：下載未儲存資料後重新載入，依最新資料重新填入所需修改。不要直接匯入整份過期資料。
- 不同案件可各自儲存；同一案件內的零件／送鍍紀錄仍共用案件版本。新增、刪除或排序也可能需要處理清單排序衝突。

## 維護注意事項

- 新表：state_records、state_storage_meta、state_commits。舊 company_state 保留為轉換當時的快照，之後不再同步更新。
- **轉換後不可直接回退舊版程式**，否則會讀到舊快照。回退須先將最新分筆資料完整還原為舊格式。
- 變更與版本、重試識別碼在同一個 D1 交易提交；任一步失敗全部回復。
- 仍會在讀取及伺服器驗證時組合完整資料，尚未實作分頁讀取。分筆後 D1 讀取列數可能增加；本更新不代表無限容量或免除平台用量限制。
- 保留現有案件數／紀錄數驗證。單筆變更最大 1,000,000 bytes、單次請求最大 8 MiB，避免異常大型輸入；這不是全部資料的容量限制。
- 本更新沒有升級付費方案或修改帳務設定。

驗證：48 項自動測試通過，包含舊資料轉換、超過 1.5 MB、同時修改不同／相同案件、重試去重、交易回復、角色權限、照片功能。另通過模擬瀏覽器 DOM 操作流程；未連接正式 Cloudflare 資料庫測試或部署。
