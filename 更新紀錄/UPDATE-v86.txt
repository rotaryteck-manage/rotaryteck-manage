這次改了什麼
1. 每週與每日排程的「工作項目」改成正式下拉選單，手機與電腦一致；工作內容仍由人員手動輸入。
2. 後台「工作排程區」可設定下拉選單內容及順序。已從選單刪除的舊名稱仍可原樣儲存，但不能用新排程新增未設定文字。
3. 每日格內固定依序顯示「工作紀錄、請假紀錄、當日各項紀錄」。完全移除舊「收／領料紀錄」入口及其空白位置。
4. 新增庫房案件時不再自動建立收料或領料紀錄；倉管或主管需依實際情況手動登記。
5. 發送測試通知的接收人加入「全員（所有已開啟通知的裝置）」。發送前會再次確認，只送給啟用中人員、未停用的人員通知及有效裝置。
6. 通知規則與通知紀錄預設收合；裝置通知狀態依人員收合，標題顯示裝置數與狀態，減少後台長頁面。
7. 後台加入通知金鑰狀態：可分辨缺少公開金鑰、缺少私密金鑰、缺少主旨、格式錯誤、公私鑰不配對及設定正常。檢查結果不會顯示或傳回私密金鑰。
8. 管理者刪除某台通知裝置後，該裝置下次進入系統會取消瀏覽器內的失效訂閱、清除舊裝置編號，按鈕恢復為「開啟通知」，不再停在「重新綁定通知」。
9. 補上排程選項授權者的後台入口，並統一新收合區與手機按鈕樣式。

VAPID_PRIVATE_KEY 怎麼確認
1. 部署v86後，用具有「後台設定」權限的主管進入後台通知區，查看「通知金鑰狀態」。
2. 正常應顯示「通知金鑰設定正常且互相配對」。這是最直接的檢查，不會洩露私鑰。
3. 若顯示「缺少 VAPID_PRIVATE_KEY」，請確認它設在目前正式Worker的Production秘密變數，不是Pages、Preview或另一個Worker；名稱必須完全為 VAPID_PRIVATE_KEY，設定後重新部署。
4. 若顯示「VAPID_PRIVATE_KEY 格式錯誤」，私鑰應是43個Base64URL字元，不可包含引號、前後空格或換行。
5. 若顯示「公開金鑰與私密金鑰不配對」，需把同一組產生的VAPID_PUBLIC_KEY與VAPID_PRIVATE_KEY一起設定後重新部署，不能混用兩組金鑰。
6. 請勿把私鑰貼到對話、GitHub、wrangler.jsonc或任何前端檔案。

安裝順序
1. 升級前先備份Cloudflare D1與R2。
2. 解壓本包，把根目錄內容依相同路徑更新到GitHub專案根目錄，不要再包一層資料夾。
3. 執行 npm run build。
4. 執行 npm run deploy。v86沒有新增SQL遷移，但部署命令仍會確認並套用尚未套用的既有遷移。
5. 保留正式環境既有SUPABASE設定、VAPID_PUBLIC_KEY、VAPID_SUBJECT、VAPID_PRIVATE_KEY Secret及D1/R2綁定。
6. 部署後關閉舊分頁，手機網站／捷徑完全關閉再重開，依 v86-驗收步驟.txt 測試。
7. 先用自己的裝置測試個人通知與刪除裝置流程；確認正常後，才測「全員」。全員測試會真的通知所有符合條件的裝置。
