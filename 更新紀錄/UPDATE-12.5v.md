# 12.5v：通知排程執行隔離

## 範圍

僅修正通知背景執行方式、診斷與版本顯示。未修改既有表單、框框、排版、通知時間、對象、文字、權限設定、頁面五分鐘靜默更新或 12.4v 功能。

## 程序邏輯

1. 既有 `*/3 * * * *` 保留。Cron 只送出經 HMAC 驗證的啟動要求，不在同一次執行計算全站並完成所有裝置加密。
2. 在同一資料庫交易建立執行紀錄、持久待辦與心跳。一個時間點不重複建立；同時只允許一個執行中的批次。
3. 各規則分別執行，只載入該規則所需資料。線材／電鍍只讀提醒所需欄位，不載入圖片、檔案或完整製作配置。
4. 檢查已完成的每日規則；未全數完成時也會排除已有成功收據的裝置，降低重複工作量。
5. 按收件人建立發送待辦。每台裝置的 Web Push 加密與 HTTP 發送在獨立請求執行，繼續使用既有送達收據、原始裝置名單及通知編號。
6. 線材／電鍍多筆仍合併成原本的一則摘要；批次收據以單次資料庫操作讀寫，避免紀錄數量增加造成查詢次數暴增。
7. 使用四條工作通道，每條最多接續八個階段，避免無限制自我呼叫。大量待辦超出此輪額度時留在資料庫，由下一次三分鐘排程接續。因此大批量或中斷時不承諾所有手機三分鐘內收到。
8. 中斷或失敗的階段經至少 90 秒可重新領取，下一輪自動接續，最多三次。裝置重試仍遵守原本上限；每批最多 32 次裝置嘗試、每日最多 200 次的既有額度保留。
9. 新增本版一次性啟用界線，只套用自動背景執行。更新前未送出的通知、舊裝置名單及舊重試不會自動湧入。既有補發預覽、勾選與歷史紀錄保留，仍可人工確認後補發。
10. 加入中文階段診斷；平台回傳非 JSON 錯誤頁時顯示資源受限／HTTP 回應異常，不誤報為 JSON 語法錯誤。
11. 新增待辦表只保留完成／失敗的診斷資料七天；不刪除通知紀錄、鈴鐺、請假、週會、品檢或任何業務資料。

## 驗證限制

本地測試、原生 workerd/D1/WebCrypto 模擬及 Wrangler 部署乾跑不等於正式環境 10ms CPU 額度驗收。原生測試使用假帳號、假裝置及模擬推播服務，沒有操作正式公司資料或傳送真人通知。

正式上線後應確認至少連續三輪後台檢查完成，並觀察 scheduled 與 `/api/notification-runtime125` 的 fetch 執行紀錄。Cron 成功只證明啟動成功，不能單獨作為全部通知已完成的證據。

完整自動測試 396 項通過。原生 workerd 模擬確認七人發送七次，第二輪零重送，未向真實推播服務發出任何請求。Wrangler 部署乾跑通過。

若部署時間已晚於某規則今日的設定時間，該則不因修復自動補送。測試應設定更新後的未來時間，或等待下一天；缺漏由既有補發清單確認。
