# 12.3v 排程推播修復與舊通知隔離

## 修正範圍

- 排程原生推播與週會背景派送改用 Workers 支援的 manual 轉址模式。遇到 3xx 直接失敗，不追蹤、不把授權資料轉送。
- 料件既有即時推播實作、通知條件、接收人、文字設定、時間、跳轉和其他介面不改。
- 名稱／職位旁版本標示更新為 12.3v。

## 程序邏輯

1. 資料庫遷移時一次記錄更新分界，後續部署不移動。先套用遷移，再部署新版程式。
2. 更新前已到時間但未生成的每日排程通知，不在新版補跑。更新前已建立的通知裝置範圍、舊發送列、請假與週會等待事件，不再自動補送。
3. 更新後新到時間的通知正常發送。翌日例行通知照常產生；保留原本三分鐘檢查與防重複規則。
4. 更新前失敗通知加入原有「補發」勾選清單。查看清單不會發送，也不會重設次數；必須勾選並確認。
5. 僅 Invalid redirect value 這次相容性錯誤允許一次額外人工補送機會；並行操作也只記錄一次。其他錯誤不放寬重試上限。
6. 已成功的裝置跳過、只使用原先凍結的裝置名單、新綁定裝置不接收舊通知。人員停用、權限及現行指定接收人仍檢查。
7. 舊通知人工補送若失敗，也不轉入自動重試。原有失敗紀錄保留，不删除歷史。
8. 備份包含補送機會紀錄；還原時保留新資料庫的更新分界，避免歷史還原造成舊通知自動重送。

## 測試

- 完整回歸，另加 7 項涵蓋 manual／302、排程程式入口、更新前到期隔離、舊重試隔離、只勾選才補送、預覽無副作用、舊等待紀錄、凍結裝置、防重複、並行一次補送及分界初始化。
- 本機 workerd 模式驗證推播加密、manual fetch 可執行、201 成功、302 拒絕；只用受控模擬服務，沒有送出公司通知。受本機 binary 限制，冒煙測試使用 2026-08-06 相容日期；正式網站設定保持 2026-09-21 不改。
- 原有七人通知的資料庫呼叫上限 43 次測試保留，並驗證原有備份還原。
- Worker 建置與 Wrangler 部署預檢。
- 未自動按補發、未發送公司測試通知。正式手機是否跳通知仍須實機驗收。

## 檢查項目

1. 右上角版本顯示 12.3v。
2. 等一輪檢查，舊通知不大量跳出；歷史紀錄仍可查看。
3. 新增一條測試通知規則（不要僅改已發送的舊規則時間），指定自己並設未來時間；不按立即檢查或補發，確認後台自動發送、装置成功、手機有通知。
4. 再等一輪，相同通知不重複。
5. 點舊規則的補發：查看清單不發送；只有勾選確認的對象收到；成功裝置和新綁定裝置不收到舊提醒。
6. 確認 Invalid redirect value 不再出現，料件即時通知維持正常。
7. 舊通知這次若人工補送仍失敗，檢查真實新錯誤；不應持續在背景重送。
