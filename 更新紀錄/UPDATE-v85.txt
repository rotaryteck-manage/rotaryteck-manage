這次改了什麼
1. 修正排程權限及多人競態：整批全部成功或退回；每日權限不能改每週資料。
2. 排程綁定員工ID，改名不丟分派；回報保存工作名稱快照。
3. 料件及照片索引一同儲存；刪除全部照片並保留失敗清理的重試工作。
4. 資料／照片匯出包含全部10張；每日出送貨CSV補齊項目、數量、人員、來源；台北日期篩選。
5. 完整資料備份納入排程、回報、權限、通知與照片索引；全部照片備份附原始儲存物件清單。
6. 倉庫歷史改逐筆儲存與分段排序，不再截掉最舊2,000筆；正常追加只更新新增紀錄與一段排序。
7. 修正通知後台裝置清單、整個人與單一裝置暫停、失敗原因及通知紀錄。
8. 加入每5分鐘通知排程，使用台北時間，當天時間已過可補執行，防止同一規則重複發送。
9. 共用裝置換帳號需重新綁定；公鑰變更重新訂閱且保留管理者暫停；登出取消本機訂閱。
10. 工作項目保持手填並提供常用建議；回報只選已分派工作。移除重複照片預覽；保留相機、相簿、10張上限、必填及800KB壓縮。
11. 手機料件詳情傳正確ID、標題以純文字處理；舊收領料入口依歷史保留；照片快取有容量與併發限制。
12. 人員排序有獨立授權及API；設定權限可讀選人名單，無須額外取得修改人員資料的權限。
13. 統一後台按鈕高度、留白、緊湊圖示、勾選框及文字框；保留各區配色與手機16px輸入設定。
14. 統一建置，Android安裝補丁納入標準建置，舊補丁指令可繼續使用。

安裝順序（必讀）
1. 更新前，先在Cloudflare備份現有D1資料庫及R2照片。舊版後台「全部資料」不包含所有排程表，不可只靠該按鈕作升級前完整備份。
2. 解壓本包；把根目錄內檔案依相同路徑更新到GitHub專案根目錄，不要包在另一層資料夾。所有worker、dist、drizzle、build.mjs、package檔都要一起更新。
3. Cloudflare建置：npm run build。舊命令 node apply-android-v80.mjs && npm run build 也可使用。
4. 部署：npm run deploy。它會先建置，再套用D1遷移，最後部署Worker。新增0016、0017、0018三個遷移；不可跳過、改名或反覆手動重跑0017。
   若使用其他部署方式：先執行 npx --yes wrangler@4.118.0 d1 migrations apply rotaryteck-manage-db --remote，再部署新Worker。
5. 保留Cloudflare既有SUPABASE設定、VAPID_PRIVATE_KEY Secret及D1/R2綁定。此包只含公開通知金鑰；私鑰必須與公鑰配對，沒有讀取或替換私鑰。
6. 關閉其他仍開著舊版本的分頁，手機網站/捷徑關閉重開，再依驗收步驟測試。
7. 新排程器部署後會依「已啟用」的規則及接收人發送真正通知。若目前規則不準備發给全員，部署前先停用規則，先用自己的裝置驗收後再開啟。
